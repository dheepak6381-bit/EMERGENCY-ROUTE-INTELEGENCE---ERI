## Phase 1 — Firebase Project Bootstrap (Step-by-step)

### 1.1 Create Firebase Project
1. Go to [console.firebase.google.com](https://console.firebase.google.com)
2. Click **Add project** → name it `eri-dispatch`
3. Enable Google Analytics (optional but recommended for demo metrics)
4. Click **Create project**

### 1.2 Enable Firestore
1. In Firebase Console → **Firestore Database** → **Create database**
2. Select **Start in production mode** (we'll add proper rules)
3. Region: `asia-south1` (Mumbai) — closest to India demo location
4. Click **Enable**

### 1.3 Enable Firebase Hosting
1. In Firebase Console → **Hosting** → **Get started**
2. Follow wizard (we'll configure via CLI)

### 1.4 Get Google Maps API Key
1. Firebase Console → Project Settings → **Your apps** → **Google Maps Platform** OR go to [console.cloud.google.com](https://console.cloud.google.com)
2. APIs & Services → Credentials → **Create credentials → API key**
3. Restrict the key:
   - **Application restrictions:** HTTP referrers
   - Add: `localhost`, `127.0.0.1`, `*.web.app`, `*.firebaseapp.com`
   - **API restrictions:** Restrict to the 5 APIs listed above

### 1.5 Firestore Security Rules (for demo)
```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{document=**} {
      allow read: if true;
      allow write: if true; // Demo only — lock down for production
    }
  }
}
```

### 4.2 Emergency Type Selector
5 types: Cardiac ❤️ / Trauma 🩹 / Burns 🔥 / Respiratory 💨 / General 🏥
Selecting a type sets `specialty_match` weighting in the scoring engine and changes urgency framing text.

### 4.3 Hospital Scoring Engine (`scoring_engine.dart`)
```dart
// Weights (tunable via constants)
const w1 = 0.5;  // ETA — fastest gets highest score
const w2 = 0.3;  // Specialty match
const w3 = 0.2;  // Available capacity

double scoreHospital(HospitalModel h, Duration eta, String emergencyType) {
  final etaMinutes = eta.inSeconds / 60.0;
  final etaScore = 1.0 / (etaMinutes + 1); // +1 avoids div-by-zero
  final specialtyScore = h.specialties.contains(emergencyType) ? 1.0 : 0.0;
  final capacityScore = 1.0 - (h.currentLoad / 100.0);
  return (w1 * etaScore) + (w2 * specialtyScore) + (w3 * capacityScore);
}
```
Each card shows the **plain-English reasoning string** built from which factors dominated.

### 4.4 Directions API Call (with live traffic)
```
GET https://maps.googleapis.com/maps/api/directions/json
  ?origin={incident_lat},{incident_lng}
  &destination={hospital_lat},{hospital_lng}
  &departure_time=now
  &traffic_model=best_guess
  &key={API_KEY}
```
Traffic severity badge: `duration_in_traffic / duration > 1.3` → Heavy, `> 1.1` → Moderate, else Light.

### 4.5 Animated Route Polyline
Route decoded → list of `LatLng` points → draw-in animation over 800ms using a `Timer` that progressively reveals points (simulates computation visually).

### 4.6 Firestore Real-time Listeners
- `StreamProvider` on `hospitals` collection → reactive hospital cards
- `StreamProvider` on `road_conditions` collection → overlay on map
- On any change → Riverpod auto-recomputes derived providers → hospital ranking updates, map overlay updates, status ticker fires

### 4.7 Adaptive Re-routing (Simulation Panel)
A toggleable panel styled as "⚙ Ops Control" — not obviously a demo button.
Actions:
- **Block road segment** → writes `status: "construction"` to `road_conditions/{id}`
- **Spike hospital load** → writes `current_load: 95` to `hospitals/{id}`

App reacts within ~1 second via Firestore stream → re-scores hospitals → if best hospital changed, ticker fires: *"⚠ St. Mary's now at 95% — switched to City General (6 min ETA, 38% capacity)"*

### 4.8 Status Ticker
Slides in from top-right, persists 8 seconds, fades out. Queued if multiple events fire. Color-coded by event type (red = degradation, cyan = improvement).

### 4.9 "How This Works" Panel
Expandable bottom sheet / modal explaining:
- Scoring formula in plain language
- What live traffic means for routing
- How Firestore drives re-optimization

> [!IMPORTANT]
> **Firebase Project Name**: The plan uses `eri-dispatch` as the Firebase project ID. Do you want a different name? Firebase project IDs are globally unique.

> [!WARNING]
> **Google APIs Billing**: Maps Directions API + Distance Matrix API require a billing account on Google Cloud (though the $200/month free credit covers hackathon usage). Make sure billing is enabled on your Google Cloud project before running the app.

> [!NOTE]
> **State Management**: I've chosen **Riverpod** (flutter_riverpod ^2.6.0) over Provider. It handles async streams, error states, and derived computed state more cleanly — critical for the adaptive re-routing feature. This is the recommended choice.
